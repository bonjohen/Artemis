# Project Review

**Date:** 2026-05-07
**Scope:** Full
**Project:** Artemis Calendar
**Reviewer:** Claude Code

## Executive Summary

Artemis is a well-structured data science pipeline with 131 passing tests and clean linting. The codebase is healthy overall — consistent import style, clear module boundaries, and good use of parameterized SQL where it matters. The most significant findings are: (1) a DOM-based XSS in the lesson viewer, (2) 21 of 54 source modules (39%) have zero test coverage including the entire load/ and observe/ layers, (3) three dead-code files that duplicate logic in active modules, and (4) documentation drift across README.md and startup.md. Recommended priority: fix the XSS, delete dead code, then address test coverage for the load and parse layers.

## Findings

### [HIGH] F-01: DOM-based XSS in lesson viewer via unsanitized markdown rendering

**Category:** Security
**Evidence:**
- `docs/lessons/lesson.html:217-238` — The `lesson` query parameter is read from the URL (`params.get('lesson')`), used to construct a fetch path (`${lesson}.md`), and the fetched markdown is rendered via `container.innerHTML = marked.parse(md)` with no sanitization.
- `docs/lessons/lesson.html:242` — The `lesson` parameter is interpolated directly into an error message via template literal and set as `innerHTML`. The CSP allows `'unsafe-inline'` in `script-src`, so inline event handlers injected through the error path could execute.
- No DOMPurify or equivalent sanitizer is loaded anywhere in the project.

**Impact:** Crafted URL can inject HTML/script into the error path. The `marked.parse()` path would also execute injected script if markdown sources were ever user-contributed.

**Fix:**
1. Add DOMPurify (`import DOMPurify from 'https://esm.sh/dompurify'`) and sanitize both `innerHTML` assignments.
2. Use `textContent` for the user-controlled `lesson` value in the error message instead of HTML interpolation.
3. Remove `'unsafe-inline'` from `script-src` by moving inline scripts to a separate `.js` file.

### [HIGH] F-02: 39% of source modules have zero test coverage

**Category:** Tests
**Evidence:**
21 of 54 source modules have no test file that imports or exercises them:

- **Entire `load/` layer untested** (3 files): `loader.py`, `staging.py`, `warehouse.py`
- **Entire `observe/` layer untested** (2 files): `logging.py`, `run_manifest.py`
- **Most of `parse/` untested** (3 of 4): `category_parser.py`, `leaderboard_parser.py`, `vote_manifest_parser.py`
- **Most of `extract/` untested** (5 of 7): `collector.py`, `images.py`, `manifest.py`, `timeline.py`, `vote_api.py`
- **`cli.py` untested** (433 lines, 15 commands)
- **Mart writers untested**: `models/marts.py`, `optimize/marts.py`, `validate/marts.py`
- **Synthetic helpers untested**: `ground_truth.py`, `profiles.py`
- **Validation checks untested**: `validate/checks.py`

**Impact:** Regressions in the data loading pipeline, observation layer, or CLI would not be caught by tests. The load layer is the core ETL path — data corruption there would propagate downstream silently.

**Fix:** Prioritize test coverage for:
1. `load/loader.py` and `load/warehouse.py` — test the ETL path with in-memory DuckDB
2. `parse/vote_manifest_parser.py` and `parse/leaderboard_parser.py` — test JSON parsing with fixture data
3. `cli.py` — test at least `cmd_status` and `cmd_run_all` argument handling

### [MEDIUM] F-03: Three dead-code files never imported anywhere

**Category:** Dead Code
**Evidence:**
- `src/artemis_calendar/extract/timeline.py` — Contains `fetch_photos_js()` and `extract_photo_data()`. Zero imports across all source and test files. The actual parsing logic lives in `parse/timeline_parser.py` which is actively used.
- `src/artemis_calendar/extract/vote_api.py` — Contains 6 functions (`fetch_vote_manifest`, `parse_vote_manifest`, etc.). Zero imports anywhere. Parsing logic is reimplemented in `parse/vote_manifest_parser.py` and `parse/leaderboard_parser.py`.
- `src/artemis_calendar/validate/checks.py` — Contains `check_row_counts()`, `check_duplicate_guids()`, `run_all_checks()`. Zero imports anywhere. Not wired into any CLI command or pipeline.

**Impact:** 139 lines of dead code that increase maintenance surface and could mislead someone reading the codebase about where logic lives.

**Fix:** Delete all three files. They are fully superseded by their counterparts in `parse/` and `validate/`.

### [MEDIUM] F-04: Documentation drift — README.md and startup.md out of sync

**Category:** Documentation
**Evidence:**
- `README.md:190` — States "26 lessons across 3 blocks." Actual: 29 lessons across 4 blocks (`docs/lessons/block4/` exists with lessons 028-030).
- `README.md:29-45` — Package layout table omits `review/` module (7 implementation files, fully functional).

**Impact:** Misleads new contributors or the user's future self about project state. The test count gap (96 vs 131) is particularly confusing.

### [MEDIUM] F-05: Missing CSP on lessons index page

**Category:** Security
**Evidence:**
- `docs/lessons/lessons.html:1-8` — No `Content-Security-Policy` meta tag, unlike `lesson.html` which has one.

**Impact:** Inconsistent security posture between two pages in the same viewer.

**Fix:** Add the same CSP meta tag from `lesson.html` to `lessons.html`.

### [MEDIUM] F-06: SQL queries use f-string interpolation for table names

**Category:** Security
**Evidence:**
- `src/artemis_calendar/cluster/clustering.py:28` — `f"SELECT image_sk, embedding_vector FROM {table}"` where `table` is a function parameter (highest risk)
- `src/artemis_calendar/validate/checks.py:17` — `f"SELECT count(*) FROM {table_name}"` (from `information_schema`)
- `src/artemis_calendar/cli.py:38` — Same pattern
- `src/artemis_calendar/synthetic/generator.py:72` — `f"DELETE FROM {table} WHERE synthetic_flag = true"` (hardcoded list)
- `src/artemis_calendar/features/embeddings.py:86` — `f" LIMIT {limit}"` where limit is an int parameter

**Impact:** Negligible exploitation risk (all sources are internal), but the pattern is fragile. `clustering.py:28` is the only case where the table name arrives as a function parameter.

**Fix:** Add an allowlist check to `clustering.py:_load_embeddings()`:
```python
ALLOWED_TABLES = {"feature_image_embedding", "feature_description_embedding"}
if table not in ALLOWED_TABLES:
    raise ValueError(f"Invalid table: {table}")
```

### [MEDIUM] F-07: `.gitignore` missing entries for secrets, IDE, and OS files

**Category:** Operations
**Evidence:**
- `.gitignore` contains only Python build artifacts (`__pycache__/`, `*.pyc`, `*.egg-info/`, etc.) and DuckDB files. Missing:
  - `.env`, `.env.*` — environment variable files (plausible since `config/settings.py` reads env vars)
  - `*.key`, `*.pem` — key/certificate files
  - `.vscode/`, `.idea/` — IDE configs
  - `Thumbs.db`, `desktop.ini`, `.DS_Store` — OS metadata files
- `.claude/scheduled_tasks.lock` is git-tracked — a transient lock file that should not be versioned.

**Impact:** `git add .` could stage secrets or IDE config. The tracked lock file causes unnecessary noise.

**Fix:** Add to `.gitignore`:
```
.env
.env.*
*.key
*.pem
.vscode/
.idea/
Thumbs.db
desktop.ini
.DS_Store
.claude/*.lock
```
Remove `.claude/scheduled_tasks.lock` from tracking: `git rm --cached .claude/scheduled_tasks.lock`.

### [MEDIUM] F-08: Hardcoded optimization weights and thresholds not in config

**Category:** Architecture
**Evidence:**
- `src/artemis_calendar/optimize/methods.py:134-138` — MMR method weights: `w_pop=0.35`, `w_appeal=0.20`, `w_monthfit=0.15`, `w_redundancy=0.20`, `w_uncertainty=0.10`
- `src/artemis_calendar/optimize/scoring.py:68-74` — Objective function weights: `2.0, 1.5, 0.8, 0.5, -1.0, -0.3` (completely independent from method_e weights — unclear if intentional)
- `src/artemis_calendar/models/batch_scores.py:38-39` — Beta prior: `prior_alpha = 2.0`, `prior_beta = 8.0` (no justification)
- `src/artemis_calendar/optimize/month_fit.py:59-103` — Hue thresholds for month-color fitting: `60, 300, 180, 220, 80, 220, 40, 40`
- `src/artemis_calendar/render/layout.py:39-41` — Windows-only font paths: `"C:/Windows/Fonts/segoeui.ttf"`, `"C:/Windows/Fonts/segoeuib.ttf"`, `"C:/Windows/Fonts/segoeuil.ttf"`

**Impact:** Cannot tune model weights without code changes. Font paths fail on non-Windows systems. Two sets of optimization weights (`methods.py` vs `scoring.py`) serve different purposes but the relationship is undocumented.

**Fix:** Move the optimization weights and Beta prior to `config/settings.py` as named constants. Add a comment to `scoring.py` explaining how its weights relate to `methods.py` weights. Platform-detect font paths in `layout.py` with fallback.

### [MEDIUM] F-09: Parsers lack input validation — silent failures on malformed data

**Category:** Architecture
**Evidence:**
- `src/artemis_calendar/parse/vote_manifest_parser.py:12` — `json.loads()` then `data.get("items", [])`. No check on item shape (expects `guid` and `link` fields).
- `src/artemis_calendar/parse/category_parser.py:11` — `data.get("buckets", ...)` with silent empty-list fallback if key is missing/None.
- `src/artemis_calendar/parse/leaderboard_parser.py:11-29` — Three functions, all `json.loads()` + `.get()` with silent fallbacks.
- `src/artemis_calendar/parse/timeline_parser.py:19` — Accesses `data["photos"]` without try-catch. Will crash with KeyError if "photos" key is missing (inconsistent with other parsers that silently fallback).

**Impact:** Malformed JSON from upstream sources silently produces empty datasets, making failures hard to diagnose. `timeline_parser.py` is the only parser that will crash on malformed input — inconsistent behavior.

**Fix:** Add a `_require_key(data, key)` helper that raises `ValueError` with a clear message. Apply consistently across all parsers. Silent fallbacks should be explicit `log.warning()` + return empty, not silent `.get()`.

### [LOW] F-10: HTTP client uses spoofed browser User-Agent

**Category:** Security
**Evidence:**
- `src/artemis_calendar/extract/download.py:51-55` — UA impersonates Chrome 131.
- `src/artemis_calendar/extract/images.py:117-120` — Same spoofed UA.

**Impact:** Misidentifies the client to NASA/R2 CDN. Unnecessary since both permit automated access.

**Fix:** Use an honest UA: `"ArtemisCalendar/1.0 (data pipeline)"`.

### [LOW] F-11: `lesson.html` error path leaks file path structure

**Category:** Security
**Evidence:**
- `docs/lessons/lesson.html:224` — Fetch path `${lesson}.md` built from unvalidated user input, allowing traversal probing.

**Impact:** Minor information disclosure. Limited by same-origin policy and static local context.

**Fix:** Validate `lesson` against pattern `^block\d+\/\d{2,3}_[a-z_]+$` before fetching.

### [LOW] F-12: No CI/CD pipeline

**Category:** Operations
**Evidence:**
- No `.github/workflows/`, `.gitlab-ci.yml`, `Makefile`, or equivalent CI configuration anywhere in the repo.
- Tests (131 passing) and linting (ruff) are run manually only.

**Impact:** No automated verification on commit/push. Regressions could be introduced without detection until someone manually runs `pytest`.

**Fix:** Add a minimal GitHub Actions workflow or a `Makefile` with `test` and `lint` targets for local pre-commit use.
