# Project Review

**Date:** 2026-05-07
**Scope:** Full
**Project:** Artemis Calendar
**Reviewer:** Claude Code

## Executive Summary

Artemis is a well-structured data science platform with 168 passing tests and clean linting. The codebase is architecturally sound — consistent naming, clear module boundaries, parameterized SQL, and good separation of concerns. The most significant findings are: (1) a path traversal vulnerability in the selection API that allows reading/writing files outside the intended directory, (2) overly permissive CORS configuration, (3) DOM-based XSS in error handlers, (4) extensive SQL subquery duplication (14+ copies of the same "latest run" pattern), and (5) roughly half the source modules lack dedicated tests. Recommended priority: fix the path traversal, tighten CORS, then address query duplication and test coverage.

## Findings

### [CRITICAL] F-01: Path traversal in selection API routes

**Category:** Security
**Evidence:**
- `src/artemis_calendar/web/routes/selection.py:72-77` — GET handler:
  ```python
  def get_selection(name: str = "current"):
      path = SELECTIONS_DIR / f"{name}.json"
      if not path.exists():
          return {"name": name, "assignments": [], "notes": ""}
      data = json.loads(path.read_text(encoding="utf-8"))
  ```
- `src/artemis_calendar/web/routes/selection.py:80-90` — PUT handler:
  ```python
  def save_selection(body: SelectionSave):
      SELECTIONS_DIR.mkdir(parents=True, exist_ok=True)
      path = SELECTIONS_DIR / f"{body.name}.json"
  ```

The `name` parameter is user-supplied and used directly in path construction. A request like `GET /api/selection?name=../../etc/passwd` or `PUT` with `name: "../../../foo"` can read or write files outside `SELECTIONS_DIR`. Python's `Path /` operator does not prevent `..` traversal.

**Impact:** Arbitrary file read (GET) and write (PUT) on the host filesystem, limited to `.json` extension.
**Fix:** Validate the `name` parameter against a strict pattern:
```python
import re
if not re.match(r'^[a-zA-Z0-9_-]+$', name):
    raise HTTPException(status_code=400, detail="Invalid selection name")
```
Or resolve and check: `if not path.resolve().is_relative_to(SELECTIONS_DIR.resolve()):`

### [HIGH] F-02: CORS allows all origins

**Category:** Security
**Evidence:**
- `src/artemis_calendar/web/app.py:35-40`:
  ```python
  app.add_middleware(
      CORSMiddleware,
      allow_origins=["*"],
      allow_methods=["*"],
      allow_headers=["*"],
  )
  ```

**Impact:** Any website can make cross-origin requests to the API, including the selection PUT endpoint (F-01). Combined with path traversal, a malicious page visited by a user running the dev server could write arbitrary files.
**Fix:** Restrict to `["http://localhost:8420"]` or make configurable. For a local dev tool this is lower urgency than F-01, but the combination is dangerous.

### [MEDIUM] F-03: DOM-based XSS in error handlers

**Category:** Security
**Evidence:**
- `src/artemis_calendar/web/static/js/app.js:37` and `:50`:
  ```javascript
  app.innerHTML = `<p>Error loading page: ${err.message}</p>`;
  ```
- `src/artemis_calendar/web/static/js/pages/selection.js:156`:
  ```javascript
  display.innerHTML = `<p style="color:var(--atlas-bad)">Scoring error: ${err.message}</p>`;
  ```

Error messages are injected via `innerHTML`. If an error message contains HTML (e.g., from a crafted API response or fetch failure), it executes in the DOM.

**Impact:** Low in practice (requires controlling error message content), but violates defense-in-depth.
**Fix:** Use `textContent` instead of `innerHTML` for error messages, or create elements programmatically.

### [MEDIUM] F-04: No Content-Security-Policy headers on web app

**Category:** Security
**Evidence:**
- `src/artemis_calendar/web/app.py` — no CSP middleware or headers set.
- The lesson viewer at `docs/lessons/lessons.html` correctly sets CSP via meta tag, but the main web app does not.

**Impact:** No defense-in-depth against XSS. If an injection vector is found, there's no CSP to limit damage.
**Fix:** Add a middleware that sets `Content-Security-Policy: default-src 'self'`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`.

### [MEDIUM] F-05: SQL subquery duplication across 7 files

**Category:** Architecture
**Evidence:**
The "latest score run" subquery appears **14 times** across 7 files:
- `review/queries.py` — 4 occurrences (lines 123, 184, 212, 233)
- `web/queries.py` — 4 occurrences (lines 45, 71, 118, 146)
- `web/db.py` — 3 occurrences (lines 44, 60, 94)
- `web/routes/clusters.py` — 1 occurrence (line 86)
- `web/routes/stats.py` — 1 occurrence (line 60)
- `optimize/__init__.py` — 1 occurrence (line 64)

The "latest cluster run" subquery appears **9 times** across 5 files:
- `web/queries.py` — 3 occurrences (lines 52, 79, 126)
- `web/db.py` — 1 occurrence (line 77)
- `web/routes/clusters.py` — 2 occurrences (lines 64, 93)
- `review/queries.py` — 2 occurrences (lines 116, 173)
- `optimize/__init__.py` — 1 occurrence (line 90)

**Impact:** If the scoring or clustering schema changes (e.g., adding a `run_status` filter), 23 SQL fragments need synchronized updates. This is the highest-risk maintenance burden in the codebase.
**Fix:** Extract `latest_score_run_subquery()` and `latest_cluster_run_subquery()` helper functions that return the SQL fragment string, and call them from all query sites.

### [MEDIUM] F-06: README lesson count outdated

**Category:** Documentation
**Evidence:**
- `README.md:198`: States "29 lessons across 4 blocks"
- Actual count: 35 lessons across 5 blocks (block5 with 6 web app lessons was added in commit `0077613`)

**Impact:** Minor — misleads contributors about project scope.
**Fix:** Update line 198 to "35 lessons across 5 blocks (infrastructure, statistical methods, optimization, validation, web app)."

### [LOW] F-07: Hardcoded font paths in render/layout.py

**Category:** Architecture
**Evidence:**
- `src/artemis_calendar/render/layout.py:41-56` — Platform-branching with hardcoded absolute paths:
  ```python
  if platform.system() == "Windows":
      FONT_REGULAR = "C:/Windows/Fonts/segoeui.ttf"
  ```

The code has platform detection (Windows/Linux/macOS) which is reasonable, but the paths are not configurable and will fail on non-standard font installations.

**Impact:** Low — the rendering pipeline is a batch process, not user-facing. Failure is visible and fixable.
**Fix:** Add `FONT_REGULAR`/`FONT_BOLD`/`FONT_LIGHT` overrides to `config/settings.py` with the current values as defaults.

### [LOW] F-08: Test coverage gaps in core modules

**Category:** Tests
**Evidence:**
Source modules with no corresponding test file:
- `config/database.py`, `config/settings.py` — database connection, path constants
- `observe/logging.py`, `observe/run_manifest.py` — observability layer
- `extract/manifest.py`, `extract/collector.py`, `extract/images.py` — extraction pipeline
- `load/staging.py`, `load/warehouse.py` — load layer (test_load.py covers loader.py only)
- `models/batch_scores.py`, `models/category_scores.py`, `models/composite.py`, `models/pairwise_scores.py`, `models/reliability.py`, `models/marts.py` — scoring (test_scoring.py covers the aggregate entry point only)
- `validate/marts.py` — validation marts
- `web/db.py`, `web/queries.py`, individual route files — web layer (test_web_api.py covers integration only)

168 tests exist and pass, but coverage is concentrated in integration-style tests that exercise the entry points. Individual module logic is not unit-tested.

**Impact:** Regressions in internal logic (e.g., a scoring formula change) won't be caught until they propagate to integration test assertions.
**Fix:** Prioritize tests for `models/` (scoring formulas are the intellectual core) and `load/warehouse.py` (data integrity). The web layer is adequately covered by test_web_api.py for a dev tool.
